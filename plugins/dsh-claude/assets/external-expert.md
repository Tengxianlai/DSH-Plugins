# 外场专家（场外专家）：Claude Opus 5.5

你有一条外场专家线（也叫场外专家、第二意见）：`claude` 工具。它把问题、背景和材料打包给 Claude Opus 5.5，
开启扩展推理，拿回一份独立判断。它不执行代码、不读写工作区，只读你给它的材料并回答。

这不是“遇到什么都问一下”的装饰性工具。它是外场专家：请它，是因为你确实需要一个
不在局中的脑子。

## 什么时候请它

满足任意一条就够了：

1. **专业难度明显偏高。** 问题跨了你不熟悉的领域（架构取舍、安全边界、法律/合规、
   医学/金融/工程判断），或者一步错代价很大，靠猜不如问。
2. **你多次被反驳或反复出错。** 同一个结论被用户、测试、日志或其他 agent 反复打回，
   说明你的模型里有系统性盲点；继续自己绕大概率还是同一个坑。
3. **你卡住了，不知道下一步。** 反复调试无进展、两个方案都说不通、信息不足又无法
   自己补、开始在同一组命令之间循环。迷茫时最该做的不是再试一次，而是换一个视角。
4. **用户点名。** 用户说“问 Claude”“找外场专家”“要个第二意见”“让 Opus 看看”，
   直接按用户要求调用。
5. **高风险决定。**  irreversible 的操作、对外发布、大额成本、安全相关变更，在动手
   前要一份独立复核。

## 什么时候不要用

- 简单事实查询、格式转换、你已经确定且验证过的小改动。
- 用户明确禁止外部调用，或材料不允许发送给第三方模型。
- 你只是想把活外包出去、不想自己读材料。外场专家需要你先把问题讲清楚。
- 材料里有不该外发的密钥、隐私、未公开数据。先把敏感内容脱敏或去掉。

## 怎么准备一次咨询

外场专家看不到你的会话，只看到这次请求。**brief 的质量决定回答的质量。**

### `task`：只写问题

写清楚：

- 要它判断/决定/复核什么；
- 成功标准是什么，哪些约束不能破；
- 你要它给结论、给方案对比，还是指出你错在哪。

不要写“帮我看看”“分析一下”这种没有验收标准的话。

### `source`：把局讲清楚

按这个顺序写，能写多具体就多具体：

1. 目标与背景（这是什么项目、现在到哪一步）。
2. 你已经试过什么，结果是什么。
3. 收到的反驳/报错原文，以及你认为可能的原因。
4. 相关代码、日志、配置、数据（只贴必要片段，标清文件与行号）。
5. 你现在的两个（或几个）候选方案，以及你犹豫的点。
6. 明确约束：不能改什么、必须兼容什么、时间/成本限制。

如果同一份背景要问多次，`source` 保持逐字一致；把新问题放进 `task`。这样缓存前缀
才能命中。

### `files`：让它自己看

- 图片：`png/jpg/jpeg/webp/gif`，截图、场景图、设计稿、报错截图。
- PDF：规格书、论文、合同、报告。
- 文本：`txt/md/csv/json/srt/vtt/yaml/html/fountain/log` 等。
- 音频/视频不支持；请先转成文字或抽帧图片。
- 每个附件会带“文件 N：路径”的标签，回答里可以让它按路径指认。

## 参数怎么选

| 参数 | 建议 |
|---|---|
| `reasoning` | 默认 `high`。真正难、跨领域、高风险就用 `high`；一般复核可用 `medium`；只做快速校对才用 `low`。 |
| `max_tokens` | 默认随推理档位（high 为 24576）。除非要压成本，不用改；它必须大于思考预算。 |
| `cache_ttl` | 默认 `1h`。同一份背景预计还会追问，保留 1h；确定只问一次，用 `5m` 降低首次写入成本。 |

缓存是自动的：system 指令和 `source`/`files` 组成的固定背景在最后一个断点前，`task`
在断点后。第二次用同样背景提问会读缓存，返回里会带 `cache_read_tokens`；首次会带
`cache_write_tokens`。如果两次都读写为 0，通常是背景太短，没到缓存最小长度。

## 怎么用它的回答

外场专家是第二意见，不是最终裁决。

1. **先核对材料引用。** 它说“文件 2 里写了 X”，回到原文件确认 X 真的存在；它可能看错，
   也可能把你的描述当成事实。
2. **分清结论与推测。** 它标了“不确定/材料不足”的地方，不要在自己的回答里升级成确定。
3. **和你的判断冲突时，不要立刻投降，也不要立刻否定。** 把冲突点列出来，做一次本地
   验证（跑测试、查文档、看日志），再决定。
4. **它说材料不足时，补材料再问。** 不要逼它猜；猜出来的结论比没有更危险。
5. **向用户汇报时标明来源。** 说清楚“这是外场专家（Claude Opus 5.5）的意见”，以及
   哪些点你已经本地核实、哪些还没有。

## 一个合格的调用

```text
claude(
  task="我们准备把上传服务从本地磁盘切到对象存储。请判断这个迁移方案有没有会丢数据的边界情况；如果有，指出最小修复。",
  source="""目标：上传服务 200 QPS，文件 1KB-2GB，现写本地磁盘，计划双写对象存储后切读。
已试：单写对象存储，压测发现 1GB 以上失败率 3%；回滚脚本未覆盖分片上传。
报错：PutObject 超时后客户端重试，产生重复对象。
候选：A 双写 + 校验；B 先切小文件；C 引入队列。
约束：不能停机，不能改客户端 SDK，月底上线。""",
  files=["docs/storage-design.pdf", "logs/upload-timeout.log", "diagrams/flow.png"],
  reasoning="high",
  cache_ttl="1h",
)
```

## 边界

- 它看不到你的工作区，也不会执行命令；所有事实要么在 `source`/`files` 里，要么不存在。
- 它不会替你做决定。最终取舍、改动和验证仍然由你负责。
- 一次调用是一个独立请求，不续接上一次的对话；多轮追问要把上一轮结论和新材料一起
  重新给出（背景不变时缓存会命中）。
