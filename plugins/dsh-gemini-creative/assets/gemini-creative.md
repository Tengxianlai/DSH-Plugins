# Gemini 创作与审看

`gemini` 是文学/文字工作的合作者：写、改、读、比。Gemini 4 Argon 能同时读文字、图片、PDF 和片段，适合“看完一堆材料再给判断”的活；但技术质检不是它的主场，那部分交给本地工具和 DeepSeek 子代理。

## 分工：什么时候交给 Gemini

- 写：剧本、分镜、对白、旁白、角色小传、文案、改写、续写。
- 看：场景图、分镜图、概念图、生成素材，和剧本/分镜表对照，找场景错误、语义错误、道具或光线矛盾。
- 读：PDF、长文、采访记录、设定集、CSV/JSON 清单，做结构梳理、一致性检查、版本比较。
- 选：同一场景/同一镜头的多个版本，判断哪一版最贴近想要的气质。
- 短片/音频：只有确实需要“整体判断”（表演、节奏、连续性、气质）时才附片段，并在调用时说明 `media_purpose` 与 `local_evidence`。普通图片对照不需要这些，照常传。

## 什么时候不交给 Gemini

- 技术测量默认走本地：ASR 转录、逐帧信号扫描、ffprobe、解码、联排册与音画时标；由DeepSeek子代理整理核对。身份、口型与表演需要有明确范围的实际媒体复核，不能由这些数值直接推成结论；必要的Gemini综合判断仍可按目的/证据规则调用。
- 自动工具的输出只是证据，不能直接当结论：抽帧不能当动作/口型终审，ASR 不能证明口型，片段级判断也不能说成整片审看。本地工具跑出的证据由子代理核对后再用。
- 不要在 Gemini 里“多切几个小视频反复问”来代替本地检查：先裁片、抽帧、转写，再用一次有目的的综合判断。

## 新项目先加载或建立资产登记

- AI影片开工或恢复时先加载 `ai-video-production`。该技能提供实际可执行的 `production/cli.mjs` 入口：登记、批准／采用证据、按镜头构造请求、required/hash参考清单、本地ASR和扫描；其Base位置决定安装路径，不写死旧项目目录。仅写普通文本时无需新建视频项目。
- 跨项目资产登记（角色卡、场景卡、批准关键帧、声音参考等）应在开工时先加载并复用，不要只看文件夹里有什么。
- 登记与预算是声明和流程记录，不认证人的身份。实际字节、来源槽位、批准根的继承及证据范围由程序核对；不要用模型PASS替代用户或授权导演的决定。
- 已批准的角色卡、场景卡、关键帧必须是“被引用”的资产，不能只躺在目录里而不进入后续生成与审看。

## 怎么问

**用自然语言说清楚背景和目的，不要写成命令清单。** 就像跟一个刚进组的合作者交代事情：

- 我们在做什么项目；
- 材料在哪：长文放 `source`，图片/PDF/片段路径放 `files`；
- 你想让它看什么、比较什么、判断什么；
- 什么算“有问题”（只有任务确实需要时才说）。

只有在结果格式真的重要时，才在 `task` 里指定长度、格式或输出结构；其余时候让它自己判断该说什么。

## 参数

1. `task`：你的问题或请求，自然语言。背景、材料位置、关注点都写进去。
2. `source`：长文本材料（剧本、访谈、设定）。没有长文就不传。
3. `files`：图片、PDF、视频/音频片段、文本文件的本地路径或 URL。工具会自动给每个附件加“文件 N：路径”的标签，Gemini 可以按路径指认。
4. `reasoning`：默认 `medium`；密集对照或深度分析用 `high`；快速看一眼用 `low`。
5. `max_tokens`：默认 16384，含思考 token；要它一次写很长时再调高。
6. 音/视频附件额外要求：`media_purpose`（必须由 Gemini 整体判断什么）和 `local_evidence`（ffprobe、裁片/抽帧、本地 ASR 的路径或摘要）；用户明确要求 Gemini 直接看片段时，可置 `user_requested_media_review=true` 代替本地证据。
7. `auto_escalate`：默认 false，一次调用只付一次请求；只有显式置 true，才允许“思考耗尽预算且无正文”时放大一次预算重试（上限 65536）。

支持：png/jpg/webp/gif/bmp、pdf、mp4/mov/webm、mp3/wav/ogg、txt/md/csv/json/srt/yaml/html。附件总量上限 12MB；本地文件会先按体积预检再读，远端流式截断；更大的视频先本地裁片段或压缩。签名 URL 的 query 会被去掉，不会进入提示词。

## 用量与失败

- 返回里带 `attempts`：每个 HTTP attempt（正常请求、401 回退、显式预算重试）的状态和 usage。
- `usage_complete` / `unknown_usage_attempts` 说明有没有 attempt 的 token 未知；未知不会按 0 冒充已计量。
- 空正文失败时，错误信息里也有 attempt 数和累计 usage，费用可见。
- 默认没有自动放大预算；不要让同一个问题在看不到费用的情况下反复付费重试。

## 示例

```
gemini(
  task="我们现在在做一部雨夜短片。剧本和分镜表在 source 里，场景图在 files 里，路径按场次命名。请对照检查：时间、地点、人物、道具、光线有没有明显对不上的地方？只指出你最确定的几处，并说明依据。",
  source="（剧本 + 分镜表全文）",
  files=["scenes/s01-rain-alley.png", "scenes/s02-doorway.png", "scenes/s03-rooftop.png"],
  reasoning="high",
)
```

```
gemini(
  task="这是第一版剧本。帮我看看第三幕的节奏是不是塌了：哪里信息重复、哪里冲突没有升级。先不要改，只诊断。",
  source="（剧本全文）",
)
```

```
gemini(
  task="这几张是同一场景的三个版本。我们想要'雨夜、狭窄、压迫感'，不要明亮和开阔。你觉得哪一张最接近，为什么？",
  files=["scenes/v1.png", "scenes/v2.png", "scenes/v3.png"],
  reasoning="medium",
)
```

```
# 只有一个短片段需要整体判断时；技术项已由本地工具跑过并由子代理核对。
gemini(
  task="这是我们定下的8秒镜头。本地已用ffprobe核过时长、抽帧看过构图、ASR转过对白。请整体判断：片段的表演和节奏是否成立，气质是不是我们要的'压抑但克制'。只评估此片段，并说明你能看到/听到的依据；这些技术证据尚不能证明口型或身份已通过。",
  files=["clips/s01_take3_trim.mp4"],
  media_purpose="整体判断表演、节奏与气质是否成立",
  local_evidence="ffprobe 8.0s/24fps；抽帧 6 张；本地 ASR 两句",
  reasoning="high",
)
```

## 拿到结果之后

- 直接把它当合作者的意见来读，不要加“这是 Gemini 说的”前缀，除非用户问。
- 它说“不确定”的地方就是不确定；不要把猜测转成事实。
- 技术结论仍以本地工具 + 子代理核对为准；Gemini 的片段观感不能替代 ASR、逐帧或口型检查。
- 需要它再看一轮时，把上一轮结论和新增材料一起给它，问题写得更具体。
- 超过 20 万字符的正文会被截断；要完整长文就分段。
