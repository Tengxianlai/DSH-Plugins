# dsh-gemini-creative

按需加载的“创作与审看”技能：写剧本、对白、旁白、文案，或者拿场景图、分镜、PDF 和剧本对照时，把活交给 `gemini`（见 `dsh-gemini` 插件）。

## 路由：什么交给 Gemini，什么留给本地

- **Gemini**：文学/文字创作与改写、长文分析，以及需要整体判断的图片/短片（表演、节奏、气质、连续性）。
- **本地工具 + DeepSeek 子代理**：ASR 转录、逐帧扫描、ffprobe、解码、接触表、音画同步、口型/身份/表演核验等技术质检。
- 自动工具输出只是证据：抽帧不能当动作/口型终审，ASR 不能证明口型，片段级判断也不等于整片审看。
- 音/视频附件在工具侧需要 `media_purpose` + `local_evidence`（或用户明确要求的 `user_requested_media_review=true`）；图片对照不受限。
- 不要用“多切几个小视频反复问 Gemini”代替本地检查。

## 新项目的资产登记

技能正文要求新项目先加载或建立跨项目资产登记（角色卡、场景卡、批准关键帧、声音参考等），并复用已批准资产，而不是只看文件夹里有什么。登记入口由项目生产流程/根代理提供；当次会话没有入口时，先按项目已批准资产清单登记并沿用，不要另起一套。技能正文不写死任何机器的绝对路径。

## 为什么是技能而不是提示词

- 技能只在匹配时加载，正文不进默认 system prompt，不增加每个会话的常驻上下文，也不会给上游的提示词指纹添新句子。
- 技能由模型按 description 自行选择；描述里同时写了中文触发词（写剧本、对白、旁白、文案、分镜、场景图、素材对照、长文分析）和英文触发词，并明确排除技术质检，避免中文请求漏触发或把 ASR/逐帧检查误派给 Gemini。
- 正文可改：`assets/gemini-creative.md` 在每次加载时读取，改完新会话即生效，不用重启（目录条目的元数据改了才需要重启）。

## 内容

技能正文覆盖：

- **写**：剧本、分镜、对白、旁白、角色小传、文案、改写/润色/续写。
- **看**：场景图、分镜图、概念图、生成素材，和剧本/分镜表对照，找场景错误、语义错误、道具或光线矛盾。
- **读**：PDF、长文、访谈、设定集、CSV/JSON 清单，做结构梳理、一致性检查、版本比较。
- **选**：同一场景多个版本，判断哪一版最贴近想要的气质。
- **路由**：技术质检走本地工具与子代理；抽帧/ASR 只作证据；片段判断不等于整片审看。
- **资产登记**：新项目先加载/建立跨项目资产登记，批准的角色卡、场景卡、关键帧要被引用复用。
- **怎么问**：用自然语言交代背景和目的，不要写命令清单；长文放 `source`，图片/PDF/片段路径放 `files`；只有结果格式真的重要时才指定长度或结构。
- **参数**：模型固定 argon；`reasoning` 默认 medium；音视频要 `media_purpose`/`local_evidence`；`auto_escalate` 默认 false。
- **用量**：`attempts`、`usage_complete`、空正文失败的累计 usage 都可见；不靠反复付费重试试错。

## 安装

由 `plugin_manager` 的 `install_bundle` 托管安装，target 用本目录的绝对路径（相对仓根是 `plugins/dsh-gemini-creative`）。

技能目录在会话开始时注入；装好后**开新会话**才能看到 `gemini-creative`。

## 依赖

运行时依赖 `dsh-gemini` 提供的 `gemini` 工具。两个插件分开安装；只装技能不装工具时，技能会指向一个不存在的工具。

## 自检

```sh
node --check index.js
node scripts/verify.mjs
```

自测检查：provider 注册、候选元数据（名称/描述/invocation/source）、正文可加载、正文包含 `gemini`、场景图触发词与中文触发词、技术质检路由、资产登记提示、音视频预检参数与用量透明度、正文不含机器绝对路径。
