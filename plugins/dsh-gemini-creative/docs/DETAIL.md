# Gemini 创作与审看

一个按需加载的技能：写剧本、对白、旁白、文案，或者拿场景图、分镜、PDF 和剧本对照时，把活交给 `gemini`（Gemini 4 Argon）。

## 触发条件

描述里同时包含中文和英文触发词，并明确排除技术质检：

- 写：剧本、分镜、对白、旁白、角色小传、文案
- 看：场景图、分镜图、概念图、生成素材与剧本/分镜表对照
- 读：PDF、长文、访谈、设定集、CSV/JSON 清单
- 选：同一场景多个版本的比较

不触发：代码、工具调用、短事实问答、用户明确要主模型本人写，以及 ASR 转录、逐帧扫描、ffprobe/解码、口型/身份/表演核验这类技术质检（走本地工具 + 子代理）。

## 技能正文说了什么

1. **分工**：文学/文字和整体判断交给 Gemini；ASR、逐帧、ffprobe、解码、音画同步等由本地工具 + DeepSeek 子代理承担。抽帧和 ASR 只是证据，不能当口型/身份/表演终审，片段级判断也不等于整片审看。
2. **资产登记**：新项目先加载或建立跨项目资产登记（角色卡、场景卡、批准关键帧、声音参考等），批准资产必须被引用复用；登记入口由项目生产流程/根代理提供，正文不写死绝对路径。
3. 用自然语言交代背景和目的：我们在做什么、材料在哪、要它看什么、什么算问题。
4. 长文放 `source`；图片、PDF、片段、文本文件路径放 `files`。工具会自动给每个附件加“文件 N：路径”标签。
5. 音/视频附件要 `media_purpose` + `local_evidence`（或用户明确要求的 `user_requested_media_review=true`）；`auto_escalate` 默认 false，不为看不到费用的自动重试买单。
6. 模型固定 `gemini-4-argon`；`reasoning` 默认 medium，密集对照或深度分析用 high，快速看用 low。
7. 拿到结果后直接当合作者意见来读；“不确定”就是不确定，不要转成事实；技术结论以本地工具 + 子代理核对为准。

## 与 gemini 的关系

技能只负责“什么时候调、怎么问”；真正发请求、拼干净 system prompt、加载图片/附件、做音视频预检、过滤思考内容、记录每次 attempt 的 usage 的是 `dsh-gemini` 的 `gemini` 工具。两个插件分开安装，技能正文在加载时读取，改 `assets/gemini-creative.md` 不需要重启。

## 限制

- 技能是否被选中由模型按 description 判断，不是硬编码路由；要 100% 确定时，直接在请求里说“用 gemini 看”。
- 技能目录在会话开始时注入，装好或改元数据后需要开新会话。
- 工具侧附件合计上限 12MB（本地先 stat 预检、远端流式截断），支持图片/PDF/片段/文本；docx/xlsx 需要先抽文本或转 PDF。
- 资产登记的具体入口取决于项目当前生产流程；本技能只规定“先加载/登记并复用”的原则，不提供虚构路径。
