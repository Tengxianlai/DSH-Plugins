# 0001 交付下载的落地方式

**日期**：2026-10-19 ｜ **状态**：生效中

## 背景

远程浏览器（Mac/PC 访问跑在 WSL 上的 DSH）拿不到文件：交付卡片只有「侧边栏预览」
与「主机侧原生打开」两条动作，前者受 iframe 沙箱限制、后者作用在服务端那台机器上。
用户要的是"把文件存到我自己的机器上"。

## 决策

### 1. 做成独立插件包，不改 `node_modules` 里的官方包

官方包是 npm 安装的**构建产物**（`~/DSH_ZONE/tools/dsh-alpha/node_modules/@deepseek-ai/*`），
直接打补丁能 10 分钟见效，但：

- 每次 `npm install` 升级都会丢，且丢了**没有任何提示**（按钮消失，看不出原因）；
- 与"第三方包保持原样、只做对账"的既有纪律相冲突（本机唯一被改过的官方文件是
  `dsh-sandbox-local/lib/index.js`，与显示无关，但也说明这类补丁需要专门记账）。

所以走官方扩展点：卡片动作槽位 `deliverables.file.actions`（catalog 记录
`replaceRisk: none`，明确允许"新 id 并排加一格"）、`deliverables.review.file.actions`、
以及 `sidebar.right.tab.document.actions`。插件在 profile 的 `node_modules` 里注册，
升级 DSH 不影响它。

### 2. 挂在本机层（`~/.dsh/machine.yml`），不挂共享层

包只装在 WSL 的 `~/.dsh/profiles/web/node_modules/`，Mac 上没有；
写进 `~/.dsh/cordis.patch.yml`（两台机器一致、入库）会让 Mac 解析不到包名而加载失败。
代价：本机层没有 HMR，**必须重启 dsh-web** 才生效（客户端插件清单本来也是启动时构建的）。

### 3. 宿主半体零第三方依赖

profile 的 `node_modules` 里没有 `@deepseek-ai/*`（那些包在 `dsh-alpha/node_modules/`），
所以宿主半体不能 `import '@deepseek-ai/dsh-fs'` 之类。全部自己写：`basename`、
扩展名→MIME 表、失败码映射。浏览器半体同理由 ModuleLoader 静态模块解决
（`react`、`ui-primitives` 都在静态表里）。

### 4. 路由坐标与官方同族路由一字不差

`/api/present.download` 对 `/api/present.open`、`/api/changes.download` 对
`/api/changes.open`：只换最后一段动词，校验链（回读事件/摘要 → 解析主机路径 →
往返核对）照抄官方实现，只把"调原生程序打开"换成"读字节 + 附件头"。
好处是浏览器半体的改写规则退化成"末段 `.open` → `.download`"这一条通用规则
（对账脚本会验证两半确实对得上）。

### 5. 预览标题栏不新增宿主路由

该槽位的 ownerProps 直接给 `absolutePath`，用官方 `/api/file?path=` 即可；
文件名由 `<a download>` 属性给（`/api/file` 不设 `Content-Disposition`）。
少一条路由、少一处可出错的地方。

## 被否掉的选项

- **改官方包加按钮**：见 1。
- **让预览 iframe 允许 same-origin + 绝对 `/api/file` 图片**：那是官方渲染策略，
  改它等于替上游做安全决策（沙箱是为隔离不可信 HTML），且我们改了升级即丢。
- **用 `fetch` + Blob 下载**：要把整个文件读进页面内存，大文件受限，且拿不到
  浏览器原生下载的断点/进度行为。

## 后果

- 升级 DSH 后需要重新核实：官方路由名、三个槽位的 id 是否变（对账脚本会红）。
- 官方若把"下载"并入交付卡片，本插件可以退场（记在 STATE.md 第 5 节）。
