# 独立复核与集成决策

日期：2026-11-16。复核范围是本目录保留的三份 root 初稿快照，不包含后续 H3 预算/任务代码，不代表对最终实现的认证。

DeepSeek 独立复核对初稿进行了本地反例测试；外场专家 Claude Opus 5.5 又复核了证据与授权边界。它的核心意见是：必须分开字节事实、范围有限的机器观测和人／代理判断；保留预算硬闸门，不能把本地声明伪装成安全认证。

采纳的修复：

- 请求 envelope 必须取 args 后重新校验，不信旧 validation 快照。
- 资产、根引用、实际槽位和来源声明要对应；相同内容的多种登记不能无条件全部算成已使用。
- 导出清单重算实际哈希；检查软链接项目根；处理大媒体时分块读。
- audit 与 paid-production gate 区分，审计不能污染实际输入覆盖。
- QC 按证据类型检查源、范围和散列，保留历史。结构化扫描完成不等于内容通过。
- ASR 使用本机已验证的 ffmpeg→numpy 路线，不依赖当前不兼容的直接 PyAV 解码，不下载模型。
- 残留锁需要可核实的失活恢复；活进程的锁不能仅因超时就被抢走。
- 登记项目未能关联本地源/QC时，明确拒绝裸 source_task_id 升档；一般 API 能力与项目核验能力分别说明。

没有采纳的推导：

- 不引入逐片强制人工审批，也不用同一执行者可读写的 0600 文件假装解决认证。
- args.dialogue 不能替代 prompt 中实际要说的台词。允许标点/空白一致化，不允许漏字或改写原句。
- 黑帧/静止可能是合法设计；机器只报告观测和可疑信号，不自动否定内容或重生素材。
- ASR 同音字差异不自动触发重生；保留原始转录，由授权代理说明复核范围与判断依据。
- 文件名或物理归档位置不能推翻后来的明确采用记录；版本哈希、实际依赖和采用范围才是依据。

最终验收仍需主代理审查最终差异、针对真实反例跑离线测试、实跑现有短源ASR，再核托管安装的实际生效状态。没有新付费媒体生成冒烟测试。
